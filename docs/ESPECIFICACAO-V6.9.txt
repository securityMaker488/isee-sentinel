# 1. MISSÃO PRINCIPAL

Atue como uma equipe multidisciplinar de especialistas em cibersegurança, arquitetura de sistemas, engenharia de software, inteligência artificial, infraestrutura, investigação forense, governança e operações empresariais.

Sua missão é projetar, implementar, integrar, auditar, testar, otimizar, documentar e evoluir o **I.See Sentinel**.

A plataforma deverá apoiar o ciclo completo de segurança:

**Importar → Identificar → Investigar → Auditar → Testar → Detectar → Proteger → Corrigir → Validar → Recuperar → Monitorar → Documentar.**

O objetivo não é desenvolver apenas um scanner de vulnerabilidades.

O Sentinel deverá ser uma plataforma integrada capaz de apoiar:

- Auditorias de segurança.
- Pentests autorizados.
- Avaliações de websites.
- Avaliações de APIs.
- Auditorias de software.
- Defesa de endpoints.
- Operações de SOC.
- Red Team.
- Blue Team.
- Purple Team.
- Análise de malware.
- Perícia digital.
- Resposta a incidentes.
- Engenharia de correções.
- Segurança de redes.
- Segurança em nuvem.
- Segurança de identidades.
- Segurança móvel.
- IoT e OT/ICS.
- Segurança de IA.
- Gestão de riscos.
- Governança e compliance.
- Continuidade de negócios.
- Serviços gerenciados de cibersegurança.

O produto deverá permitir que a I.See Technologies identifique problemas, demonstre riscos, desenvolva soluções, valide correções e acompanhe a segurança dos sistemas dos clientes.

**Não prometer segurança absoluta, cobertura de todos os ataques possíveis ou detecção perfeita.**

Nenhuma funcionalidade poderá ser declarada concluída sem implementação e testes verificáveis.

# 6. SENTINEL UNIVERSAL IMPORT LAB

Criar um módulo central para importar e analisar aplicações.

## Entradas

- URLs HTTP/HTTPS.
- Repositórios Git autorizados.
- Projetos ZIP.
- TAR.GZ.
- EXE.
- MSI.
- DEB.
- RPM.
- AppImage.
- Binários ELF.
- APK.
- AAB.
- IPA, conforme compatibilidade disponível.
- Arquivos de configuração.
- Especificações OpenAPI.
- Imagens de aplicações.
- Cópias autorizadas de homologação.

## Fluxo

**Nova avaliação → Selecionar entrada → Importar → Identificar → Validar escopo → Preparar ambiente → Escolher testes → Executar → Analisar → Corrigir → Retestar → Relatório.**

Identificar:

- Tipo de aplicação.
- Linguagem.
- Framework.
- Dependências.
- Sistema operacional.
- Arquitetura.
- Permissões.
- Requisitos de execução.
- Riscos.
- Ferramentas compatíveis.
- Necessidade de internet.

## Segurança

Arquivos importados são potencialmente perigosos.

Implementar quarentena, hashes, limites de tamanho, proteção contra arquivos compactados maliciosos, controle de expansão, proteção contra path traversal, validação de links simbólicos e proibição de execução automática no host.

# 7. SENTINEL WEB URL IMPORTER

Permitir cadastrar uma URL de site ou aplicação web.

O Sentinel deverá:

- Identificar o domínio.
- Associar o ativo ao cliente.
- Validar escopo e permissões.
- Identificar tecnologias observáveis.
- Verificar configurações e cabeçalhos.
- Avaliar TLS e certificados.
- Analisar cookies.
- Identificar endpoints autorizados.
- Sugerir testes adequados.
- Gerar planos de avaliação.
- Registrar evidências e resultados.

Permitir associar a URL a:

- Repositório Git.
- Arquivos do projeto.
- Ambiente de homologação.
- Especificações de API.
- Credenciais temporárias autorizadas.

Uma URL pública não permite, por si só, reproduzir o backend, o banco de dados ou a infraestrutura privada.

Para avaliação isolada completa, solicitar os artefatos necessários.

Proteger o próprio importador contra SSRF, redirecionamentos maliciosos e acesso indevido à rede local.

# 17. BEFORE/AFTER SECURITY COMPARISON

Permitir importar duas versões de um software ou configuração.

Comparar:

- Vulnerabilidades anteriores.
- Falhas confirmadamente corrigidas.
- Falhas persistentes.
- Novos riscos.
- Alterações relevantes.
- Evidências.
- Resultados de testes.
- Riscos residuais.

Não considerar uma falha corrigida apenas porque desapareceu de um scanner.

Exigir reteste comparável.
