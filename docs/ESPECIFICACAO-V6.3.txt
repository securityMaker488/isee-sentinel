# 4. DIRETRIZ OFICIAL — PRIVATE OPERATOR EDITION

**Esta seção é obrigatória e define o modelo de funcionamento da primeira versão do produto.**

O I.See Sentinel será inicialmente uma plataforma de cibersegurança privada, desenvolvida para uso exclusivo do fundador da I.See Technologies.

Somente o fundador terá acesso à central administrativa.

O sistema deverá ser utilizado como ferramenta própria para prestação de serviços de cibersegurança, desenvolvimento, auditoria, investigação, proteção e pesquisa.

A primeira versão não será um serviço público nem uma plataforma SaaS.

## 4.1 Identidade e autenticação

Implementar:

- Um único operador administrativo.
- Autenticação forte.
- Suporte a MFA.
- Preferência por passkeys quando viáveis.
- Armazenamento seguro de credenciais.
- Sessões protegidas.
- Bloqueio contra tentativas abusivas de autenticação.
- Revogação de sessões.
- Registro de acessos.
- Recuperação administrativa segura.

Não utilizar credenciais padrão conhecidas.

Não incluir senhas ou chaves de produção no código-fonte.

## 4.2 Interface privada

O Sentinel Command Center será acessível somente pelo operador autorizado.

Não implementar inicialmente:

- Cadastro público.
- Registro de clientes como usuários.
- Portal público de clientes.
- Sistema de assinatura.
- Pagamentos.
- Cobrança recorrente.
- Marketplace.
- Planos comerciais.
- Sistema de convites.
- Administração pública de múltiplos usuários.

Não expor o painel administrativo diretamente à internet.

## 4.3 Funcionamento local

Priorizar execução local no Debian.

O sistema deverá poder operar sem conexão contínua com a internet nas funcionalidades compatíveis com operação offline.

As dependências de rede deverão ser identificadas e documentadas.

Quando for necessário acesso remoto, utilizar mecanismos seguros e explicitamente configurados.

Não exigir uma VPS para utilizar a primeira versão.

## 4.4 Gestão de empresas e projetos

Embora apenas o fundador utilize o sistema, ele poderá administrar serviços de diferentes empresas.

Permitir cadastrar:

- Empresas.
- Projetos.
- Contratos.
- Autorizações.
- Escopos.
- Domínios.
- Aplicações.
- Servidores.
- Redes.
- Ativos.
- Vulnerabilidades.
- Evidências.
- Investigações.
- Incidentes.
- Relatórios.

Esses registros serão gerenciados pelo único operador.

Os clientes não terão acesso ao painel.

Manter separação lógica dos dados de cada projeto e organização.

## 4.5 Segurança obrigatória

A existência de um único operador não elimina a necessidade de:

- Autenticação.
- MFA.
- Controle de privilégios.
- Criptografia.
- Auditoria.
- Backup.
- Proteção de arquivos.
- Controle de execução.
- Proteção dos bancos.
- Gestão de segredos.
- Isolamento dos laboratórios.
- Aprovações para operações críticas.

O operador administrativo não deverá executar todos os serviços com privilégios máximos permanentemente.

Implementar identidades de serviço separadas e privilégios mínimos.

## 4.6 Compatibilidade multiplataforma

O Sentinel deverá ser projetado para utilização em Debian e Windows.

O núcleo da plataforma deverá utilizar tecnologias multiplataforma sempre que possível.

Capacidades dependentes do sistema operacional deverão possuir adaptadores específicos.

## 4.7 Evolução comercial

A arquitetura deverá suportar futura expansão para:

- Múltiplos operadores.
- Organizações independentes.
- Isolamento entre clientes.
- Portal de clientes.
- Controle comercial.
- Licenciamento.
- Instalações corporativas.
- SaaS.
- Serviços gerenciados.

Entretanto, não implementar toda essa complexidade antecipadamente.

**Objetivo:** desenvolver primeiro uma ferramenta pessoal de cibersegurança altamente especializada, segura e funcional, que posteriormente poderá ser transformada em produto comercial.
