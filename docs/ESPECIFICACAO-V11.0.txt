# 05 — PRINCÍPIO RUST-FIRST

**Os novos motores críticos do I.See Sentinel deverão ser desenvolvidos preferencialmente em Rust.**

A preferência não autoriza reescritas indiscriminadas.

Rust será priorizado especialmente para:

- Processamento de entradas não confiáveis.
- Execução de tarefas.
- Controle de subprocessos.
- Concorrência.
- Processamento de rede.
- Coletores.
- Análise de artefatos.
- Correlação.
- Integridade de evidências.
- Serviços locais sensíveis.
- Agentes de endpoint.

Utilizar safe Rust sempre que possível.

Todo uso de unsafe deverá ser justificado, isolado e testado.

Evitar:

- Panics em produção.
- FFI insegura sem isolamento.
- Execução ilimitada.
- Alocações não limitadas.
- Deadlocks.
- Exaustão de recursos.
- Processos órfãos.
- Operações privilegiadas desnecessárias.

Priorizar bibliotecas consolidadas, examinadas e mantidas.

Preservar Python, TypeScript, Java ou Go em componentes existentes que já sejam tecnicamente adequados.

Não transformar a plataforma artificialmente em 100% Rust.

## 6.1 Sentinel Execution Engine — Rust

Responsabilidades:

- Job scheduling.
- Task orchestration.
- Filas.

- Priorização.
- Timeouts.
- Retry.
- Cancellation.
- Backpressure.
- Process supervision.
- Resource limits.
- Plugin execution.
- State recovery.
- Audit trails.
- Error handling.

Propriedades exigidas:

- Uma tarefa não pode extrapolar escopo e permissões.
- Cancelamentos devem encerrar subprocessos associados.
- Falhas de plugins não devem derrubar todo o Sentinel.
- Tarefas interrompidas devem apresentar estado correto.
- Operações críticas devem ser auditáveis.

Considerar Tokio e tracing quando apropriados.

## 6.2 Sentinel Web/API Security Engine — Rust

Responsabilidades:

- HTTP client.
- Crawling controlado.
- URL normalization.
- Endpoint discovery.

- Finding generation.

Responsabilidades:
