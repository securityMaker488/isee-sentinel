# Registro de decisões arquiteturais

As decisões abaixo foram aceitas para a fundação em 23/10/2026. Aceitação de uma decisão não significa que seus critérios de validação já foram executados.

| ADR | Decisão e motivação | Consequência / condição de revisão |
|---|---|---|
| 001 | Monorepo npm, React/TypeScript/Vite e Fastify/TypeScript. Contratos e motores puros em `packages/core`. Reduz dispersão inicial e permite testar regras sem servidor. | Limites entre módulos devem ser preservados; extrair serviços somente diante de isolamento, carga ou ciclo de vida comprovadamente distintos. |
| 002 | Node 24 LTS como linha da fundação. Fastify 5 fornece validação e ecossistema de segurança. | O runtime observado 24.21.0 não é a atualização mais recente identificada; a fonte oficial registra 24.22.1 em 21/10/2026. Atualização administrada e retestes são necessários antes de operação. Não atualizar o sistema do usuário automaticamente. |
| 003 | PostgreSQL dedicado para serviço e PGlite separado para desenvolvimento/teste. | Não reutilizar o serviço PostgreSQL existente sem banco, credenciais e consentimento apropriados. Não compartilhar o diretório PGlite entre processos. Testes PGlite não homologam o driver `pg` nem o servidor Linux. |
| 004 | MFA TOTP obrigatório, senha com Argon2id de biblioteca mantida, sessão opaca em cookie, hash do token no banco, CSRF para mutações. | Recuperação CLI por código offline de uso único foi implementada/testada na V6.5; Passkeys/WebAuthn e reautenticação sensível são evolução. Provisionamento por CLI deve preservar sigilo do segredo TOTP. Não inventar primitivas criptográficas. |
| 005 | PolicyGate determinístico, com negação por padrão, organização derivada da sessão, operação conhecida e autorização por ativo/ambiente/prazo. | RBAC fixo é suficiente nesta fatia. Contratos, ABAC extenso, horários comerciais e múltiplos aprovadores não estão completos. Novos executores devem consumir a decisão do mesmo gate. |
| 006 | Upload lógico de caminhos relativos e conteúdo textual; sem ler caminho arbitrário no host, executar scripts ou buscar URLs. | Limita a análise inicial a conjuntos pequenos de arquivos. Arquivos binários, ZIP, disco, memória e PCAP exigirão parsers isolados com quotas antes de serem aceitos. |
| 007 | Evidência cifrada no SQL; SHA-256 dos bytes originais, auditoria encadeada e restrições contra mutação pela aplicação. | Tamanho reduzido é requisito. Chave fora do banco; sua perda impede acesso aos dados cifrados. Admin do host/banco continua no domínio de confiança. Armazenamento WORM e ancoragem externa ficam pendentes. |
| 008 | Jobs persistidos com executor único e limitado. | Sem Redis obrigatório. Sem promessa de fila distribuída ou recuperação automática. Evoluir para leases, heartbeat, quotas, cancelamento e idempotência antes de workers externos. |
| 009 | Catálogo das 14 barreiras com estado desconhecido/pendente quando não houver medição. | Configuração declarada não prova eficácia. Cada avaliação deve indicar alvo, data, teste, evidência e limite; uma regra de análise não certifica a camada inteira. |
| 010 | Nenhuma execução ofensiva, LLM remoto, remediação de produção ou captura de tráfego na fundação. | Capacidades futuras dependem de escopo explícito, isolamento e verificação de efeitos. Laboratório permanece distinto de clientes. |
| 011 | Local-first, bind de loopback, sem Docker ou cloud obrigatórios; exemplo systemd separado do app. | A instalação dos pacotes necessita acesso ao registro npm ou cache confiável. Execução básica após instalar dependências não exige SaaS. Homologar TLS, permissões e restauração antes de acesso remoto. |
| 012 | Licenças são avaliadas por componente, edição, regras e modo de distribuição; não incorporar scanners externos nesta entrega. | Nmap e regras Semgrep merecem decisão específica antes de produto proprietário. Metadado npm sozinho não substitui revisão de LICENSE/NOTICE e dependências transitivas. |
| 013 | V6.3 substitui Arch por Debian 13 Stable + KDE como alvo principal; Windows continua ambiente acessível e compatibilidade progressiva. | Migração, drivers e dual boot não foram alterados. Node do pacote padrão trixie é linha 20; runtime 24 precisa caminho e procedência próprios, homologados. |
| 014 | Um único fundador administrativo na edição privada. Organizações/projetos são dados gerenciados pelo fundador, com contexto na sessão e auditoria de troca. | Não criar contas de clientes, convites, pagamentos ou portal público. Papéis do núcleo podem permanecer como defesa e preparação futura, sem CLI de provisionamento de múltiplos usuários ativa nesta edição. |
| 015 | Endpoint Rust planejado com adaptadores nativos Linux/Windows e eventos versionados; Detection Engine deve separar alerta e incidente. | Não confundir alerta sintético real persistido com detecção de invasão real; não ativar coleta privilegiada ou controle remoto no host nesta etapa. |
| 016 | Usar maturidade M0–M6 V6.3 e curso progressivo de 22 tópicos. | M3 cobre testes específicos, M4 exige operação homologada, M6 exige validação enterprise independente. Aula entregue não comprova domínio do aluno. |
| 017 | V6.5 torna PostgreSQL local administrado o padrão e exige `DATABASE_URL`; PGlite somente via modo `embedded` explícito para desenvolvimento/testes. | Substitui o fallback implícito do ADR003. Não conecta automaticamente ao serviço PostgreSQL existente nem migra dados sem configuração. |
| 018 | Arquitetura híbrida: núcleo nativo Debian; Podman rootless opcional; Kali QEMU/KVM sob demanda em rede isolada. | Podman não é dependência do núcleo e não substitui VM para experimentos perigosos; não confundir chroot com fronteira de segurança. |
| 019 | Firebase/Supabase exclusivamente como tecnologias externas auditáveis por adaptadores futuros. | Sem infraestrutura interna dessas plataformas. Adaptadores só após validação da base e revisão de escopo/credenciais. |
| 020 | V6.5 reorganiza a formação em21 tópicos e implementação em fases0–10. | Preservar fundamentos, incluir Podman/KVM e manter AutoDefense/Self-Healing/testes no capstone. Fase 0 não executada no Windows; trabalho atual é preparatório sem alegar migração. |

Fontes para ADR 002: [releases Node](https://nodejs.org/en/blog/release), [LTS Fastify](https://fastify.dev/docs/latest/Reference/LTS/). Fontes para ADR 003/012 e obrigações: `FONTES-E-LICENCAS.md`.
